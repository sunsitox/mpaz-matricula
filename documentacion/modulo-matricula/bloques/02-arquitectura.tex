\section{Arquitectura del código}

La arquitectura de la solución tiene una sola fuente de verdad:

\begin{center}
\path{documentacion/documentacion-tecnica/documentacion-tecnica.md}
\end{center}

Ese documento está escrito en Markdown con diagramas Mermaid y cubre las
vistas 4+1 del sistema. Este bloque no repite su contenido: remite a él para
que no existan dos descripciones que se contradigan.

\subsection{Qué encontrar en ese documento}

\begin{itemize}[leftmargin=*,itemsep=0.25em]
\item \textbf{Escenarios}: actores y grupos de casos de uso.
\item \textbf{Vista lógica}: capas, proyectos, controladores y servicios de
  aplicación.
\item \textbf{Vista de procesos}: inicio de sesión y permisos, matrícula de
  punta a punta, emisión de certificados y registro de dosis.
\item \textbf{Vista de desarrollo}: proyectos, dependencias NuGet y estrategia
  de pruebas.
\item \textbf{Vista física}: producción, ambiente local, respaldo y operación.
\item \textbf{Complementos}: modelo de datos, estados, seguridad y despliegue.
\end{itemize}

\nota{Los diagramas se generan desde el propio documento. Las versiones
renderizadas están en \path{documentacion/documentacion-tecnica/diagramas/}
(\codigo{.svg} para PDF y \codigo{.png} para presentaciones), y las fuentes
Mermaid en \path{diagramas/fuentes/}.}

\subsection{Cómo se mantiene}

Si cambia la arquitectura, se edita \codigo{documentacion-tecnica.md} y se
regeneran los diagramas con \codigo{extraer\_diagramas.py}. Este bloque no se
actualiza: solo cambia si cambia la ubicación del documento.
